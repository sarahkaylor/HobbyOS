GB-241 — tag the [IDLESTUCK] dump's own proc_lock acquisition
=============================================================

Head: de8335a6 (GB-240) + the GB-241 commit, branch ticket/241-dumpself-owner.
Worktree: /home/sarah/Documents/GitHub/HobbyOS/.worktrees/gb241
SW-VM: swarm-farm-3 (verifier, debug reserve — gaming.md §5.1).

Card: the [IDLESTUCK] dump holds proc_lock while printing its rows, so the
dumper's own acquire is definitionally acq=rel+1 in every dump.  Tag it
(dump_self=1) or snapshot+release, print it, exclude it, and name the real
owner — or return the negative if no real imbalanced row remains.

What this branch adds
---------------------
- src/include/lock.h: proclock_hold_t gains `dump_self`; declares
  proclock_dump_note(int on).
- src/kernel/arch/x64/locks.c: per-CPU `plh_dump_self_pending[]`.  The dump
  calls proclock_dump_note(1) before its acquire and (0) after its release;
  proclock_hold_note() copies the flag into `dump_self` at the ACQUIRE, so the
  tag travels with the exact acquisition (not with whichever CPU later prints).
- src/kernel/arch/arm/locks.c: no-op stub.
- src/kernel/process.c [IDLESTUCK] dump: proclock_dump_note(1) before the
  dflags acquire, proclock_dump_note(0) after the release; [PROCLOCK-HOLD]
  prints `dump_self=` per CPU; the owner [LOCKDIAG] row prints `dump_self=`
  and `owner_in_user=` (owner_in_user = the watchdog's owner RIP is outside
  the kernel image: < 0x70000000 or >= USER_VA_BASE; the definition is in the
  code comment).
Dump content is unchanged otherwise; observation only.
