Pixel reads straight out of n0-postfix-1919x1079.ppm (P6, offset = len-1920*1080*3):

  (1919,1079) = (255,   0,   0)   pure red   <- the gate pixel, the LAST byte of the frame
  (1918,1079) = (255,   0, 255)   magenta
  (1919,1078) = (255,   0, 255)   magenta
  (0,0)       = ( 32,  48,  64)   fill       (kernel word 0xFF203040, B8G8R8A8)
  (960,540)   = ( 32,  48,  64)   fill

  bottom-right 64x64 region: 4095 x (255,0,255) + 1 x (255,0,0)
  whole-frame samples (every 37th row, 41st column): 1408 x (32,48,64) + 2 x (255,0,255)

So the corner pixel is the only red pixel in the frame and it sits inside the
magenta block exactly at the framebuffer's last address — a wrong or short
mapping cannot produce that pair.
