# The AArch64 folded-pointer table class — the audit list, and the gate that keeps it honest

Scope: the `const` tables of function and string pointers that the compiler folds
into `.rodata` and `ld.lld` resolves to **link** addresses, in the AArch64 kernel
image. Round 4 (WP-RELOC) made the image self-relocate those words and gated the
link on *coverage*. This doc records what is left in the tree (**§4**, the audit
list), and the second half of the gate added afterwards: an inventory check that
fails the link when a folded table is **added** or **grows** without a decision
(**§3**). Everything below is measured from the tree at the commit that added it
unless tagged otherwise.

| tag | meaning |
|---|---|
| **MEASURED** | I ran it on this VM and read the number: `tools/kernel_reloc_audit.py` on the linked image, or the tier output |
| **SOURCE** | read from the tree (file:line) |
| **INFERRED** | reasoning from the two above, not independently observed |

Reproduce every number here:

```bash
make ARCH=arm MODE=unit_tests hobbyos.elf                 # the link runs the gate
python3 tools/kernel_reloc_audit.py --by-symbol hobbyos.elf
```

---

## 1. The class, in one paragraph

A `const` table of function pointers, or of `const char *`, has its members
resolved **at link time**. On x86_64 that is correct, because the image loads at
its link address. AArch64 does not: Limine loads the kernel at a slide (measured
`0x3FA400000` in the unit tier), so code survives — `adrp`/`add` are PC-relative
— and data does not. A call through such a table branches to the link address of
the function, which holds nothing, and the CPU raises an EL1 synchronous
exception with **ESR `0x2000000`** (EC=0 "unknown reason", ISS=0, IL=1): the
field names nothing, which is why this cost three rounds. `SWARM-REPORT-WP-ARM2.md`
has the first measurement, `SWARM-REPORT-WP-RELOC.md` the second.

Two shapes are indistinguishable at the source level and both are in scope:

- `const struct nv_rm_if nv_rm_mock = { "mock", mock_device_open, ... }` — a
  static initializer of function pointers;
- `const char *const names[] = { "a", "b" }`, **and** an if-chain or `switch`
  over `const char *` returns, which clang folds into exactly that table (the
  `nv_shim_refusal_name()` case, MEASURED: six `.quad`s and a
  `ldr x0, [x9, x8, lsl #3]`).

## 2. What makes them safe now (round 4, unchanged here)

- the kernel is linked `-pie -z notext`, so `ld.lld` emits one
  `R_AARCH64_RELATIVE` per pointer word in an allocated `.rela.dyn`;
- `src/kernel/arch/arm/reloc.c` applies all of them at boot, after the `.bss`
  clear and before `main()`, and `halt()`s on anything it cannot apply;
- `tools/kernel_reloc_audit.py --gate` runs after every AArch64 link and fails
  the build if a word holding an in-image address has no applied relocation
  (measured rejection in `SWARM-REPORT-WP-RELOC.md`: reverting `-pie` gave
  `make exit 2` with 417 unapplied words on the round-4 tree).

So the tables in §4 are **not hazards** — they are the population the boot pass
serves. They stay folded deliberately: their runtime-built form is hundreds of
assignments executed at every boot, and `const` is what keeps the dispatch
tables in `.rodata` where they belong.

## 3. The second half: the inventory gate

Coverage alone cannot see a **new** table. While the `-pie` link is in place,
every folded word it contains gets its `R_AARCH64_RELATIVE`, so the coverage
check passes *by construction* — the gate would never notice. That is the gap
this change closes, in the one place that can see it: the linked image.

`--gate` now also compares the image's per-table word counts against
`tools/reloc_tables_baseline.json` (one section per kernel `MODE`, generated by
the tool, audited here in §4). The Makefile passes the mode, so the comparison
is exact for every mode that has been audited:

| image vs inventory | gate |
|---|---|
| a table the inventory does not list | **FAIL** — `NEW <table> <n> word(s)` |
| a listed table with more words | **FAIL** — `GREW <table> a -> b` |
| a listed table with fewer words, or absent | a `note:`, not a failure |
| a `MODE` with no section of its own | checked against the **union** of the audited modes (still fails on a table no audit has ever seen) |

Non-failures are deliberate: a table can only shrink or vanish by *removing*
wording — that is a reduction of the population, not a new hazard, and it does
not stop a build. `.got` slots are counted and printed but never gated: the
compiler emits them for a function's address in PIC code, they come and go with
ordinary code, and they are not author-written tables.

Measured, unit tier, on the green tree (MEASURED):

```
python3 tools/kernel_reloc_audit.py --gate --baseline tools/reloc_tables_baseline.json --mode unit_tests hobbyos.elf
# hobbyos.elf
# kernel link range [0x40080000, 0x417B060C)   .rela.dyn=429 entries (present)
# pointer words baked into static data (need relocating): 429
#   applied at boot (R_AARCH64_RELATIVE, addend in image): 429
#   NOTHING WILL APPLY THEM (left at their link address):     0
# folded-table inventory: 21 table(s) / 424 word(s), plus 5 linker-generated .got slot(s)
hobbyos.elf: reloc gate OK -- 429 kernel pointer word(s), every one applied at boot
hobbyos.elf: folded-table inventory matches -- 21 table(s) / 424 word(s) as audited [MODE=unit_tests]
```

`MODE=desktop` and `MODE=test` are audited too (19 tables / 418 words / 423
pointer words each — they do not link the unit-tier test tables), and an
unaudited mode lands on the union path:

```
hobbyos.elf: folded-table inventory matches -- 19 table(s) / 418 word(s) as audited [union of desktop, test, unit_tests]
```

An image from another tree (or another arch) can still be audited without the
inventory: `--no-inventory`.

## 5. The three anonymous tables, measured

A function-local array with no symbol of its own cannot be *named* by the tool,
so it is bucketed by section — `.rodata`, 18 words, which is three tables of six
slots each. Their contents, dumped from the `MODE=desktop` image (the same three
tables sit at different addresses in the unit image; MEASURED, `.rodata` base
`0x401ACD28` there):

| slots | first slot | pointers to | source |
|---:|---|---|---|
| 6 | `.rodata+0x198` | `"open" "close" "dup" "dup2" "readfail" "close_range"` | `fs.c:389` `fd_ev_kind_name()` — a `switch` clang turned into a table |
| 6 | `.rodata+0x300` | `l_tab_core l_tab_fd l_tab_mem l_tab_proc l_tab_tmr l_tab_shm` | `linux_compat.c:593` — the function-local `const struct l_sysent *const tables[]` |
| 6 | `.rodata+0x1a20` | `"grobj_alloc" "notifier_obj" "nvif" "svm" "gem_pushbuf" "setparam"` | `nv_shim.c:296` `nv_shim_refusal_name()` — the if-chain the round-4 report caught returning the link address of `"nvif"` |

Consequence for the gate: a **new** anonymous table in `.rodata` cannot be told
apart from one of these three — it shows up as the `.rodata` bucket growing
(`GREW .rodata 18 -> 21`), which fails the link just the same. If you want it
named, give the array a `static` name of its own; then the inventory lists it by
symbol.

## 6. When the gate fires

```
hobbyos.elf: FAIL -- folded table(s) not in the audited inventory [MODE=unit_tests]:
  NEW   nv_rm_mock_static_probe              16 word(s)  .rodata  first slot 0x0000401F7F48  nv_rm_mock_static_probe
```

Two responses are legal, and the gate message names both:

1. **Do not fold it.** Build the table at run time — member assignment on a
   non-const object cannot be folded, so every address in it is computed
   PC-relative and carries the slide. `src/kernel/nv_rm_mock.c` is the worked
   example (round 3 turned `const struct nv_rm_if nv_rm_mock = {...}` into
   `nv_rm_mock_if()`, and its thirteen lines of assignment are why the mock RM
   table is absent from §4). `nv_shim.c`'s `g_drm_refusals[]` is the second:
   `const char *` members became fixed-size arrays.
2. **Keep it, and record the decision.** One command refreshes the inventory for
   the mode, then re-links with the gate back on so the result is proven:

   ```bash
   make reloc_baseline MODE=unit_tests
   ```

   Commit `tools/reloc_tables_baseline.json` **with** the row added to §4 of this
   doc. Do it once per mode you build (`desktop`, `test`, `unit_tests` are
   audited today).

The link always succeeds before the gate speaks — the image exists when the
failure is printed, so `reloc_baseline` works on a tree that the gate just
rejected. That is also why the gate is a *link* gate and not a boot test: it
runs in seconds on the build host, with no QEMU.

### 7.1 The gate caught a real one, in the merge that landed this

The first link after merging `origin/nv/integ-swarm` (`bbca2514`, which brought
`nv/wp-units`' GRAPH_UNITS work) failed, unasked:

```
hobbyos.elf: FAIL -- folded table(s) not in the audited inventory [MODE=unit_tests]:
  NEW   g_nvif_engines                       12 word(s)  .rodata  first slot 0x0000401F8318  g_nvif_engines+0x20
make: *** [Makefile:1100: hobbyos.elf] Error 1                 (make exit 2)
```

That is `nv_shim.c:2759` — six `{oclass, name[24], engine, alloc}` rows, two
`const char *` each, added by a lane that had no reason to know about this class.
Its words *are* relocated at boot (the coverage check was green at 429/429), so
it is not a bug — it is exactly the decision the gate exists to force. Recorded
as response (b): `g_nvif_engines` is now a row in §4, its 12 words in every
mode's inventory, and `MODE=desktop` / `MODE=test` (which also link it) were
refreshed the same way. §4 and the baseline file are the record that somebody
looked.

| ARM unit | `TOOLS_SKIP=1 BROWSER_SKIP=1 ./run_unit_tests.sh` | **473 run / 0 failed / UNIT TESTS PASSED**, exit 0 |
| intel unit | `SKIP_KVM=1 TOOLS_SKIP=1 BROWSER_SKIP=1 ./run_unit_tests_intel.sh` | **590 run / 0 failed / UNIT TESTS PASSED**, exit 0 |

move for the other lanes' reasons; the merged-tip numbers above are therefore
the merged lanes' tests, green, with the guard live.

The intel run is TCG, not KVM, for one environmental reason and not a code
reason: this VM's `/dev/kvm` is `root:kvm` and this user is not in the `kvm`
group, so `-enable-kvm` dies with `Could not access KVM kernel module`
(`docs/nv-arm-reloc-evidence/tier-intel-kvm-denied.txt`). Same binary, same
assertions, slower wall clock. The intel link ran no reloc gate at all (0 gate
lines in its `build.log`), which is the "intel is untouched" check.


## 8. What this does NOT cover

- **x86_64.** `linker_x64.ld` loads at `KIMG_BASE` == link address, the intel
  link has no `.rela.dyn` and no gate, and `nv.c`'s tables (`nv_chips` and
  friends) stay folded — correct by construction. If the x64 load base ever
  moves, the class returns there and this gate needs an intel half. One
  practical obstacle, measured: the intel link rule ends with
  `objcopy -O elf32-i386`, so the finished `hobbyos.elf` is **ELF32** and this
  tool refuses it by design (`not a 64-bit little-endian ELF`); an intel half
  would have to audit the pre-objcopy image or grow 32-bit parsing.
- **`.got`.** Counted, printed, never gated (rationale in §3). A `.got` slot is
  still an `R_AARCH64_RELATIVE` and is still covered by the coverage gate.
- **Coincidence.** The audit calls any 8-byte data word whose value falls in the
  kernel link range a pointer word. A non-pointer constant that happened to look
  like an in-image address would be counted — and, having no relocation, it
  would already fail the *coverage* check, loudly. Measured today: 0 unapplied
  words in all three modes, so there is no such word in the tree.
- **Renaming.** The inventory keys on the containing symbol, so renaming a table
  reads as `NEW <newname>` + `note: <oldname> is listed but not in this image`.
  That is intended — a rename is a deliberate edit — but it means a mechanical
  rename needs one `make reloc_baseline` per mode.
- **Boot coverage.** Only the unit tier is booted here; `MODE=desktop` and
  `MODE=test` are link-checked, not booted by this change. The inventory is a
  property of the linked image, so that is sufficient for the gate, but it is
  not evidence that the desktop tier's tables are *reached* correctly at run
  time — `SWARM-REPORT-WP-SOAK.md` has the tier runs, and the desktop tier is
  the round-4 §6 open item.
- **Modes with no section.** They are checked against the union (§3): a table
  none of the audited modes links is a failure, but a table whose count differs
  only because a mode links more code than any audited mode is not caught
  exactly. Audit the mode (`make reloc_baseline MODE=<mode>`) when it matters.
