# Notes
# - munmapw: MUNMAPW and READIT are two lines of one wave, which runs them
#   concurrently; READIT ran first ("READIT absent").  Not a verdict.  Replaced
#   by tools/cp/sync/munmapwb.c, one process: W1 write+munmap+fresh-fd read,
#   W2 the same with a 17 GiB munmap span (16 GiB PROT_NONE + 1 GiB hole),
#   W3 MAP_PRIVATE stays off the file.
# - munmapwb-pre: src/kernel/linux_compat_mem.c from the merge commit f752acca
#   (main's write-back: physical frame address used as a pointer, page-by-page
#   walk) and everything else final -> kernel-mode #PF in the first munmap.
#   Fixed by 464dafcf.
# - mapfsync-pre: src/kernel/ext2_compat.c + linux_compat_fd.c from f752acca,
#   everything else final -> fdatasync leaves disk[1]=A (e2c_fdatasync answered
#   0 for the FAT16 fd before l_fd_fsync could flush).  Fixed by 0259c84c.
# - dirprobe: /JDK, /JDK/lib, /C, /JDKTMP are ENOENT because no JDK is staged
#   (none on strix); "/" lists "." and ".." once (main's getdents dot filter).
# - lockwait: the 1 s holder took the lock, the 8 s one printed "trying" and
#   got "held" only after "released": F_SETLKW blocks (vfs_compat.c vx_fcntl).
