Why EIO: kind=7 is VMK_LIB (DSO text mapped by the interpreter: Wine's code on the
NFS /CP stage).  vm.c vm_file_obj_materialize() returns -EIO whenever the page source
returns 0 inside the file, and file_obj.c nfs_obj_page() returns 0 when frame_alloc()
fails as well as when the read fails; vm_page_io_error() then marks the executable
region VM_MAP_IOERR for good and the fault becomes SIGBUS.  An out-of-frames page-in
is reported as a permanent I/O error on Wine's text, so the game's own crash handler
(and any later fault in that region) dies with it.
Proposed (vm.c, no owner this wave; H7-fault's area):
  --- a/src/kernel/vm.c
  +++ b/src/kernel/vm.c
  @@ static int vm_file_obj_materialize
       if (!beyond) {
         vm_object_unref(o);
  -      return -EIO;
  +      /* cp-hunt H9-12: a source that failed for lack of a frame is not an I/O
  +         error: -EIO marks executable text VM_MAP_IOERR for good (h4-l01) */
  +      return frame_free_count() == 0 ? -ENOMEM : -EIO;
       }
(the exact test belongs in nfs_obj_page / ext2_obj_page / file_obj_page, which know
whether frame_alloc() or the read failed).
