# Why: every exact-zero run in the game WAV came from WRITEIs of exactly period - held zeros
# (the kernel's [SND] zeros rows, a2-lane-fp5: call_all_zero=1, call_frames=480/384/182), i.e.
# alsa_write_data's lead-in.  The lead-in fires when data_in_alsa_frames == 0 and held < period.
# Wine 11.0 counts min(data_in_alsa, avail) as played each period, where avail is the FREE space:
# that equals what played since the last period only if the last period filled the buffer.  A
# client with little padding leaves the buffer part-empty, so the estimate empties data_in_alsa
# while ALSA still holds data -- 5 of the 10 game-stream zero runs in a2-lane-fp5 began with
# 13-26 ms still queued (q_vis=626..1258).  The patch counts played = data_in_alsa minus what
# ALSA still holds (buffer - avail).
